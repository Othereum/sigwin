# Slint gotchas

- **Missing glyphs render as blank. There is no per-glyph font fallback.** Malgun Gothic (UI font) lacks `✓ ✕ ➤`; Segoe UI Symbol lacks Hangul. Icons use `font-family: "Segoe UI Symbol"`; the status text switches font based on its content. Check every new symbol in a screenshot.
- **Color emoji are plain text everywhere** (reactions, emoji-only messages at 40px, inline): the patched renderer draws them in one consistent flat style. Don't add a separate emoji path (see `docs/decisions.md`). Windows has no flag emoji (🇰🇷 renders as "KR").
- Text styles, links and spoilers depend on the vendored core patch (`gui::rows::to_item` registers styled text, `gui::rows::rich_text` builds link spans). Details in `vendor/PATCHES.md`.
- Don't use `EmbedResourcesKind::EmbedForSoftwareRenderer`: it bakes only glyphs that appear in `.slint` files, so runtime Korean text loses characters.
- A `Flickable`'s max size defaults to its content size and propagates up through layouts, which can shrink the window. Set `max-width: 100000px` on Flickables inside layouts.
- Elements inside `if` can't be referenced by id from outside. Use `visible` and min/max sizes instead (see `composer-bar`).
- **Never build UI that only works by touch drag.** This is a PC app: anything that scrolls or pans must move with the mouse wheel (or another mouse-reachable control). A Flickable only takes the wheel along an axis it overflows, so a horizontal one ignores it. Wrap it in a `TouchArea` whose `scroll-event` moves `content-x` (clamped) and accepts; the Flickable rejects the event first and it bubbles to the parent. The `TouchArea` must be the Flickable's parent: as a sibling below it never sees the event (see the pack tabs in `stickers.slint`, the strip in `viewer.slint`).
- Use `content-y` / `content-height` (the `viewport-*` names are deprecated).
- `FocusScope` and a `Rectangle` without a layout don't take their child's size, and an explicit `min-height` overrides what a layout child would give. The composer gets its height from `min-height: min(composer.preferred-height, 140px)` on its FocusScope.
- **Hover over text: make the TouchArea the parent.** A TouchArea sets `has-hover` before forwarding to its children, so wrapping the bubble content in it (forwarding the layout's min/max/preferred sizes) sees hover over the TextInput; a TouchArea as a sibling below does not (the TextInput accepts the move). See `Bubble` / `MsgTools`.
- A read-only `TextInput` ignores right clicks, so they reach the bubble's `TouchArea` (`pointer-event`) even over text. Nested TouchAreas (image, attachment) forward right clicks themselves.
- **Don't replace the message model wholesale on reloads.** `set_vec` makes the ListView drop every row and re-seek, snapping the scroll position to a row boundary. Same-thread updates go through `update_rows` (prefix/suffix diff, `set_row_data` for changed rows); only thread switches use `set_vec`.
- **The ListView lays out only when drawing**, and before that the Flickable clamps `content-y` to the current (possibly stale) `content-height`. So a scroll set right after a model change can't show its target in the next frame. Thread switches use `seek-end` (huge content height, content-y past the end; the vendored repeater fix lays out the last row at the bottom). Debug one-frame glitches with headless `record DIR`.
- **Older pages keep the view in place (`hold_older`).** Loading starts two screens before the top (`check-older`), so usually the rows are inserted above the first instantiated row, which keeps the position by itself and doesn't fight a wheel scroll in progress. At the very top they don't, and shifting by the `content-height` difference is wrong (it is average x rows, and the average changes with the rows on screen). So the old first row is measured, the model replaced, the ListView seeked straight to that row's index with its own average (`set-content-y-raw`, unclamped), and the row settled at its old bottom edge via `seek_row`. That anchoring fights a wheel scroll in progress (the view shakes), so jumps (pins, quotes) keep `JUMP_MARGIN` rows above the target (`App::jump_to`) and never land near the window's first row.
- **The window moves.** At its cap each page also drops rows at the far end. `update_rows` lines the lists up on the rows they share first; a window that shares none (`Scroll::Bottom`, a far jump) replaces the model. Rows that left drop their thumbnails (`forget_unshown_thumbs`).
- **Wheel scrolling is a 180ms physics animation**, and `scrolled` fires when it starts, before `content-y` arrives. Anything that reacts to a scroll position (loading older history) must watch `changed content-y` too. Setting `content-y` during the animation doesn't cancel it: it keeps adding its remaining distance.
- **ListView reuses row instances**: a row scrolled into view often gets an old instance with new data (`repeater.rs` `ensure_updated`), so `init` alone misses it. `MsgImage` reports stickers on `init` plus `changed` of a derived id/still property. Not `changed m`: that also fires on our own `set_row_data` (e.g. dropping frames) and loops.
- **Images are sampled nearest-neighbor** by the software renderer (RGBA textures, any scale). A downscaled sticker gets jagged outlines. Thumbnails shown at a fixed size are pre-resampled in the backend to the exact physical size (`fit`: Lanczos3 down, Catmull-Rom up, in premultiplied alpha; `types::physical_px` uses the window scale factor). Upscaling matters too: some sticker packs are only ~112px. Give new image views a matching `fit` size.
- **Stretched images drift.** The renderer steps through source pixels in 1/256ths, truncated, so the error adds up across the image (8px over 1900px) and it doesn't land where exact pixels would. For anything that must line up, use sizes where source / target is a whole number of 1/256ths (`viewer::zoom`). What remains is a constant half pixel: it samples at the pixel's corner, not its center.
- **Software renderer and minimize:** it redraws only damaged regions, and UI updates arriving while minimized make it lose track of them. On restore the window was transparent except the last-changed bits. `winhook.rs` subclasses the window proc: on `WM_SIZE` restore and `WM_ACTIVATE` it flips `repaint-flip` (window background toggles between two identical-looking colors), which forces a full repaint. The same hook reports focus to the backend; polling is only a fallback. To reproduce, run `SIGWIN_DEMO=1 SIGWIN_DEMO_TICK=1`, minimize/restore with `ShowWindow`, and capture with `CopyFromScreen`. Don't use `PrintWindow` here: it forces a repaint and hides the bug.
- **A model nested in a ListView row: replace it, don't change it in place.** `set_row_data` on the row's inner model (`m.cells`) didn't show until the row was scrolled away and back. Put a new `ModelRc` in the row and `set_row_data` the row (`gui::media::thumb_arrived`). Late arrivals are the case to test: a demo that sends its data before the rows hides this.
